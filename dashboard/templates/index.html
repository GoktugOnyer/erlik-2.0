◫ ENGAGEMENTS

A customer, the assets they authorised, and everything ever run against them. Scope is enforced here rather than per run — an engagement with no scope rules authorises nothing, an explicit exclusion beats any wildcard, and a host found by enumeration stays inert until a human approves it.

▣ TEST LAB

loading…

Committed WSTG test cases. Each one runs fixed steps and asserts on the response — no model decides what to try, and every result names the case that produced it. A case whose required inputs cannot be supplied is listed as skipped with its reason, never dropped: a missing case reads exactly like a clean result.

A profile supplies this application's real endpoints. Without one, a case that needs a specific parameter is SKIPPED rather than aimed at the base URL — guessing is how the SSRF case came to be pointed at a search box and report a finding there. The two built-in profiles cover the lab targets; for a real customer, declare the endpoints below.

CREDENTIALS — THIS TARGET

Cases that need a session are SKIPPED until one is verified — on DVWA, logging in took the sweep from 4 findings to 8. Verification is DIFFERENTIAL: a session counts only when it changes the server's answer, so “captured” is not “works”. The password is encrypted at rest and is never returned by this page.
LOGIN URL is where the password is POSTed — check it. It may differ from the target: tools run inside the container and address http://dvwa, while the login runs on the host (http://127.0.0.1:8081). VERIFY URL is a protected page; without one the session is captured but never verified, and supplies nothing to a sweep.

DECLARED ENDPOINTS — THIS TARGET

What a built-in profile knows about a lab app, for your customer's app instead — no code change. Paths only: the base URL above is prepended, so a declaration cannot point a case at another host. A declared field also stops that case fanning out over discovered paths, because a human vouched for this one.

What was actually measured
Experiments varied skills on/off and playbook on/off only, and the playbook arm was the old Juice-Shop-specific block (all six, ~9 KB, every run). Playbooks are now generic and routed to the mission's classes (~1.4 KB), which is unmeasured — the numbers below describe what was replaced, not what now ships. Injecting this material costs recall on both models tested: 7B 0.114 → 0.014, 27B 0.086 → 0.014 (n = 2 per cell). Precision falls with it (0.90 → 0.07 on the 7B), so it is not trading breadth for accuracy. Giving the models their real context windows made this worse, not better, so it is not crowding. No arm varied this budget, so no value here carries a recall figure — the readout above measures bytes, not outcome.
